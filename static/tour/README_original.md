# Verifix Onboarding Tour (модель A — тур внутри Verifix)

Наложенный слой, который **ведёт пользователя по настройке прямо в реальном
Verifix**: постоянная панель-чеклист + coach-mark подсказки на настоящих
элементах + переходы между экранами Verifix + отметка выполнения.

Не зависит от AngularJS/Metronic — работает как overlay поверх страницы.

## Файлы
- `verifix-tour.js` — движок (панель-чеклист, попап-подсказки, прогресс, навигация).
- `verifix-tour.css` — стили (префикс `vtour-`, чтобы не конфликтовать с Verifix).
- `steps.js` — последовательность шагов на реальных маршрутах Verifix.
- `demo.html` — полигон: имитация экрана Verifix, чтобы посмотреть UX без стенда.

## Посмотреть UX сейчас
Открыть `demo.html` (любой статический сервер) — увидишь панель-чеклист справа,
подсветку кнопки «Добавить» и попап с объяснением «зачем».

## Встройка в реальный Verifix (тестовый стенд)
1. Положить `verifix-tour.js`, `verifix-tour.css`, `steps.js` в раздаваемую статику
   Verifix (например, `main/web/assets/tour/`).
2. В оболочку приложения (общий layout/шапка, которую грузят все страницы `/vhr/...`)
   добавить:
   ```html
   <link rel="stylesheet" href="/assets/tour/verifix-tour.css">
   <script src="/assets/tour/verifix-tour.js"></script>
   <script src="/assets/tour/steps.js"></script>
   <script>
     // запускать только для новых аккаунтов / пока настройка не завершена
     if (window.VERIFIX_TOUR_STEPS) VerifixTour.start(window.VERIFIX_TOUR_STEPS, {
       title: 'Настройка Verifix'
     });
   </script>
   ```
   (Так как UI Verifix конфигурируется через biruni, скрипт можно подключить в
   общий шаблон страницы — уточнить точку внедрения у команды Verifix.)

## Доводка под стенд (обязательный шаг)
`steps.js` — первый черновик. На стенде нужно уточнить два поля у каждого шага:
- **`selector`** — реальный CSS-селектор элемента, который подсвечиваем (кнопка
  «Создать/Добавить» на нужной форме). Сейчас стоят догадки
  (`.btn-add`, `.kt-portlet__head-toolbar .btn-primary`).
- **`check`** — как понять, что шаг выполнен. Сейчас `gridHasRows()` (в списке
  появились строки). Надёжнее — проверка через **Verifix API** (пример закомментирован
  в `steps.js`): посчитать созданные подразделения/сотрудников и т.д.

Также уточнить **маршрут ролей/доступов** (`roles`) — он на уровне biruni/core,
в исходниках vhr его нет.

## Маршруты (подтверждены по исходникам)
| Шаг | Форма Verifix |
|---|---|
| Подразделения | `/vhr/hrm/division_list` (есть импорт: `division_import`) |
| Должности | `/vhr/hrm/job_list` |
| Роли и доступы | уточнить (biruni/core) |
| Локации | `/vhr/htt/location_list` |
| Графики работы | `/vhr/htt/schedule_list` |
| Сотрудники | `/vhr/href/employee` |

## Как отдавать прогресс/данные
Прогресс тура хранится в `localStorage` (ключ `verifix_tour_progress`). Для
серверной привязки к аккаунту — заменить load/saveProgress на вызовы Verifix API.
